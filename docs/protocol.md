# Minecraft Protocol Architecture in Mineflex

Mineflex implements a decoupled, strongly typed Minecraft Java Edition protocol architecture.

---

## Codec Architecture

Rather than embedding unpack calls within high-level business logic, Mineflex standardizes serialization through `PacketReader` and `PacketWriter`:

```python
from mineflex.protocol.buffer import PacketReader, PacketWriter

# Encoding
writer = PacketWriter()
writer.write_varint(763)
writer.write_string("localhost")
writer.write_ushort(25565)
data = writer.get_bytes()

# Decoding
reader = PacketReader(data)
protocol_version = reader.read_varint()
server_address = reader.read_string()
server_port = reader.read_ushort()
```

---

## Packet Framing & Compression

Minecraft network frames consist of length-delimited byte sequences:

* **Uncompressed framing**: `[Frame Length: VarInt] [Packet ID: VarInt] [Data Payload]`
* **Compressed framing** (`threshold >= 0`): `[Frame Length: VarInt] [Data Length: VarInt] [Compressed or Raw Payload]`
  * If `Data Length == 0`: Payload is uncompressed (smaller than compression threshold).
  * If `Data Length > 0`: Payload is zlib compressed to `Data Length` bytes.

---

## Encryption

Online sessions use AES-128-CFB8 stream ciphers where the 16-byte shared secret generated by the client serves as both encryption key and initialization vector (IV). All framed bytes following the `EncryptionResponse` packet are encrypted and decrypted through `EncryptionCipher`.

---

## Version Registry (`ProtocolRegistry`)

Packets are registered by `(state, is_serverbound, packet_id)`:

```python
registry = ProtocolRegistry.for_version("1.20.1")
packet = registry.decode_packet(
    state=ProtocolState.PLAY,
    is_serverbound=False,
    packet_id=0x3E,
    payload=raw_payload,
)
```

This prevents version branching conditions (`if version == "1.20"`) across the codebase.
